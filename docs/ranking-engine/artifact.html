Ranking Engine

How eight per-recipe signals collapse into one per-user score — a filter-then-rank pipeline over the signals earlier sprints already persist. Deliberately boring: hard filters first, then a weighted average of normalized scores.

v1 · greenfield libSQL / Turso · Drizzle 8 signals · 4 new tables 2026-08-18
The score
score(user, recipe) =  Σi∈A wi · si Σi∈A wi

A weighted average, not a sum. A = signals with data present and weight > 0, so a recipe missing a signal is neither rewarded nor punished for the gap — the signal just drops out of both numerator and denominator. Result ∈ [0,1]; ×100 to display.

Pipeline

Filter, then rank

Hard constraints shrink the candidate pool before any scoring — the pattern every researched system converges on. Soft signals only ever rank what survives.

01

Filter

Allergens (always) and strict diets remove unsafe or incompatible recipes from the pool. Severity and strictness decide what counts.

excludes · no score
02

Score

Each surviving recipe gets a weighted average of six normalized soft-signal scores, each si ∈ [0,1]. Soft penalties subtract after.

weighted average
03

Sort

Rank by score, descending. Ties break by coverage → popularity → newest → id, so paging is deterministic.

stable order

Signal roster

Eight signals, two roles

Six soft signals carry a per-user weight. Allergens and diet are filters, so they carry none — "allergens are a hard filter, not a score," extended to strict diets. Popularity is registered but not yet built.

2 Difficulty soft difficulty_band weight_difficulty skill_level

Pluggable by design: popularity ships as one column + one PopularityScorer in the registry + its existing weight. No formula, filter, or schema-shape change.

Normalization · soft signals → si ∈ [0,1]

Every signal on one scale

Cost

weight_cost
s_cost = clamp( (2·budget − cost) / budget , 0, 1 )

At or under budget is ideal; ramps to 0 as cost rises to twice budget. Null cost/budget → unavailable.

Time

weight_time
s_time = clamp( (2·T − total_minutes) / T , 0, 1 )

Mirrors cost against the time budget T — one mental model for both budget-style signals.

Nutrition

weight_nutrition
s_nutr = x⁺ / (x⁺ + 57) · x⁺ = max(0, nrf)

Saturating squash, not min-max — NRF is a long-tailed per-100-kcal density. k=57 (NRF 15/3 literature mean) scores 0.5; flattens toward 1 without ever clamping distinct healthy recipes together. No target — "how healthy" is the weight itself.

Affinity

weight_affinity
s_aff = clamp( 0.5 + 0.5·mean(a_f) , 0, 1 )

Per facet a_f = +1 liked / −1 disliked / 0 neutral. Neutral baseline 0.5 — unfamiliar isn't punished.

Difficulty — asymmetric skill match

weight_difficulty

Signed distance d = recipe_band − skill_level. Cooking above your skill hurts more than cooking below it.

Hard filters · severity decides filter-vs-soft

The gates

The same declared allergen or diet routes to a hard exclude or a soft penalty depending on how negotiable the user says it is — the safety distinction the research keeps first-class. A mild aversion should never hide safe food; an anaphylactic allergy should never leak through.

Edges

Cold start & tie-breaks

Cold start

A new user with no preferences is ranked from the onboarding goals already on the users table:

save_money
weight_cost → 3
eat_healthier
weight_nutrition → 3
save_time
weight_time → 3
everything else
weight → 1

No goals at all → all weights 1, no filters, affinity flat at 0.5. Null targets make their signal unavailable rather than forcing a guess. Safe from day one, improves as preferences fill in.

Tie-breaking

  1. Signal coverage — more data, more confidence
  2. Popularity — once the column exists; a no-op until then
  3. Newest — created_at descending
  4. Recipe id — ascending; the stable final tiebreaker

Soft penalties

Applied after the average, floored at 0, additive: mild allergen −0.15, flexible-diet incompatible −0.20, any unknown-verdict −0.05. "Avoid, don't forbid."

Recorded, not built

What v1 deliberately leaves out

The richer ideas the research surfaced, deferred to keep the first version boring and correct. Each writes the same weight columns or adds one scorer — the ranker stays unchanged.

Popularity signal
A normalized 0–1 column from social-media imports + its scorer. Already registered — no algorithm change.
Learned weights
Fit coefficients to chosen-vs-skipped recipes (choice model / BPR-WARP). Overwrites the same integer columns.
Implicit feedback + decay
Learn affinity from behavior, recent events weighted more via exponential decay. Needs an events table.
Confidence weighting
Store strength-of-preference so a weak like pulls less than a strong one.
Hard-exclude ingredients
Promote a strong dislike to an exclusion filter. Today a dislike is only a soft negative.

Grounding · step-1 research

Justified, not asserted

Every choice above traces to a verified finding (3-vote adversarial checking). Honest caveat: the strongest evidence is from patents and papers, not the named consumer apps — a patent documents a pattern is claimed, not that any app ships it. And no source published a concrete severity/strictness enum; ours synthesizes the preference-vs-confidence split and the medical/ethical/preference tiering.

S1 Yum-me (arXiv:1605.07722) — filter-then-rank; restrictions as hard constraints separate from learned taste.
S2 US9230212B2 — hard exclusions block entirely; expert weight tables; time-decayed strength.
S3 Whatnot Engineering (2022) — learned latent factors (BPR/WARP), explicitly the initial model.
S4 FaST/FaRM (arXiv:2508.04698) — per-user feature-weight vector; interpretable weighted sum.
S5 US8874574B2 — stated distribution → per-criterion weights; derived defaults + override.
S6 Hu-Koren-Volinsky (US20110153663A1) — preference vs. confidence c=1+α·r.
S8 flavoreer — three tiers: medical / ethical-religious / personal preference.
S9 Healthy Meals (PMC8891920) — allergen presence as two-level flag.
