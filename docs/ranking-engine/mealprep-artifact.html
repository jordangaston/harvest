Meal Prep

Boost recipes built for batch cooking — for the users who actually want to meal prep. A weighted soft signal, never a filter.

soft boost ordinal band no new tables seeded by meal_prepping goal
The signal — fit × how much you care
contribution = weight_meal_prep · s(meal_prep_fit)
designeds = 1.00
suitables = 0.60
unsuitables = 0.15

Folds into the same weighted average as every soft signal (§ DESIGN.md). The recipe's fit is detected; the user's care is the weight. The score map is a tunable knob.

The shape

A boost, not a filter

The mirror image of kitchen equipment. Equipment is a hard filter — a physical constraint that excludes. Meal prep is a mode a user opts into: a non-prep recipe is never hidden, just ranked lower for prep-minded users. So it's a textbook weighted soft signal — one new SignalScorer, gated by a per-user weight most users leave near neutral.

Weight & cold-start

weight_meal_prep (0–3). The meal_prepping onboarding goal already on users.goals seeds it to 3 — the cleanest cold-start hook of any signal, exactly like save_money → weight_cost. No goal → default 1 (a mild universal lean; pure opt-in 0 is Q-MP1).

Detection (import)

LLM-primary, extending the categorizer call — it reads explicit intent ("meal prep," "make-ahead") and implicit suitability (servings, dish type, "keeps 5 days," "reheat"). Heuristic fallback (keeps-well dish type + high servings → suitable, never designed). Best-effort; null fit → signal drops out.

The band · why ordinal

Three buckets, not a float

Captured as a three-band classification, not a raw 0–1 — LLMs classify far more reliably than they fine-grained-score, mirroring difficulty_band. "designed" doubles as the product badge.

meal_prep_fitMeansScore
designedBuilt for it — batch quantities, "make-ahead," stores/freezes, portioned1.00
suitableKeeps & reheats fine — stews, curries, grain bowls, roasts0.60

unsuitable is 0.15, not 0 — down-weighted, not buried. Values are a calibration knob.

Mirrors nrf_score (recipe) and the weight_* columns (prefs). MEAL_PREP_FITS is a schema tuple like DIFFICULTY_BANDS. A "meal-prep friendly" UI badge just thresholds on fit === 'designed' — no separate flag.

Decisions & open questions

What's settled, what isn't

✓ Soft boost, not a filter
A mode users opt into, not a constraint — never hide a non-prep recipe, just rank it lower. User-gated by a weight.
✓ Ordinal band, not a float
LLMs classify reliably, floats poorly. Mirrors difficulty_band; "designed" = the badge.
Q-MP1 · default weight
1 (mild universal lean toward batch food) or 0 (pure opt-in for meal-preppers)? Shipping 1; your call.
Q-MP2 · decompose fit
Split into batchable / fridge-keeps / freezes / portioned for richer scoring and "freezer-friendly" filtering?
Q-MP5 · keeps-N-days
Distinguish fridge-days from freezer-friendly and surface it in the UI — same LLM call can emit it.
